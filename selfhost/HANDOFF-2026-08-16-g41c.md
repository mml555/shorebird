## What landed, and what it means

| commit | what |
|---|---|
| `72620b12` | **link 1** — Route B's prepass and both import kernels now compile with the six defines Flutter injects |
| `f2982364` | **link 2** — `injectedDefines` separated from `effectiveDefines`, so a patch's replacement compiles in the release's `-D` environment |

**The defect, stated once:** Flutter appends six defines after parsing the command
line (`FLUTTER_VERSION`, `FLUTTER_CHANNEL`, `FLUTTER_GIT_URL`,
`FLUTTER_FRAMEWORK_REVISION`, `FLUTTER_ENGINE_REVISION`, `FLUTTER_DART_VERSION`,
plus `FLUTTER_ENABLED_FEATURE_FLAGS` when non-empty). Route B received **none** of
them. Measured on a clean `flutter create` app with no flavor and no
`--dart-define`, so it was **every iOS release**, not a flavored edge case.

**The seam reads Flutter's own answer rather than reconstructing it** —
`DART_DEFINES` from `ios/Flutter/Generated.xcconfig`, obtained before the prepass
with `flutter build ios --config-only`, and re-checked after the real build
rewrites the same file. Reconstruction was rejected on measurement:
`FLUTTER_ENGINE_REVISION` comes from `engine_stamp.json` and reads `11e5695710`
while Shorebird's `engine.version` reads `40eaa0ef`, so deriving it from
`shorebirdEnv.shorebirdEngineRevision` is plausibly and silently wrong.

**The two-field split is the part to preserve.** `effectiveDefines` decides
COMPATIBILITY and is the fingerprint; `injectedDefines` feeds `compilerArgs` and
is absent from `canonicalText` / `fingerprint` / `agreesWith` **by construction**.
Flattening them would break comparability with every release cut before
`f2982364` — including all of 89–95.

**Legacy rule, narrow on a mechanism argument:** a pre-record release refuses
**only** a replacement whose own source contains `String.fromEnvironment` (or the
int/bool siblings), because that is the sole expression compiled against these
flags — a reference to one of the app's own consts resolves through the import
kernel. Refusing every patch to a pre-record release would strand 89–95 and every
`killswitch_probe` to guard against a construct almost none contain.

## The rules this session paid for

**Verify a publish by reading the DB or the API afterwards — never the CLI's exit
text, and never a same-session `releases list`.** One client talking to one server
is not an independent check. That is the whole of this lane's largest mistake.

**Verify a property through a channel that can actually witness it.** For
persistence read durable content, never host file metadata: a write that
demonstrably persisted left `mtime` and `size` **unchanged**. And a channel that
can only ever say one thing will say it — the 0-byte WAL was not evidence of no
writes, it was evidence of nothing. **Ask what a positive result would LOOK like
on the channel before reasoning from it.**

**Two review classes, needing different questions:**

| class | what went wrong | the question that catches it |
|---|---|---|
| **Missing falsifiability** | the check could not fail | *what failure state can this check actually observe?* |
| **Unreconciled evidence** | the contradicting measurement already existed and the claim was never tested against it | *what have we already measured that constrains this claim?* |

**Precommitment addresses neither.** It freezes the decision rule before the
result; it does not stop a bad premise being written into it — `G15` hit exactly
that (`e7000ba0`).

**Four false-greens in this lane**, three of one shape (an interface diff that
could not see the app's own functions; hand-simulated probe flags; a publish
verified through the same client) and one of the other (a `find` proving one
database, run hours before this lane proposed the writes went to a different
database). **Two of the four were caught by another lane, not by my controls.**
Controls are aimed at what you thought to doubt.
