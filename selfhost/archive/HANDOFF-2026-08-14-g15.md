## What did NOT close, and this is the important half

**Crash-backout FAILS.** `Engine::Run` returns `Success` when the entrypoint is
merely *invoked*, so a patch throwing inside `main()` banked **three consecutive
successes** while crashing every launch. Patch `0009` moved the seam from the `Shell`
constructor to `Engine::Run` returning — strictly better, still too early.

**And the consequence is blocking: a bad patch bricks the install.** The client never
backs it out, and **the server cannot rescue it** — withdrawal with `rollback=true`
was acknowledged by the control plane and the app still crashed every launch, because
withdrawal only reaches a device that lives long enough to poll. Cleared only by
`ios-deploy --rmtree` over USB. A real user would have to delete and reinstall.

Treat this as the blocking item for shipping Route B patches, not as a missing
nice-to-have.

## Rules this session paid for

1. **A negative device observation needs a POSITIVE CONTROL on the same instrument.**
   Five automated launches showed no UI and I was about to report that `0009` broke
   startup. Launching `airgap_probe` — PROVEN on device — showed the same thing. The
   instrument was wrong: `ios-deploy --justlaunch` quits the app. One control run
   stopped a false regression report about the engine change the goal rests on.
2. **A fixture whose BREAKAGE mimics its SUCCESS can only manufacture confidence.**
   The killswitch marker threw, killing the app before render — indistinguishable
   from the kill arm working. It now renders a red MARKER FAULT banner instead.
3. **`localhost` on a device is the PHONE.** A wrong `base_url` produces a perfectly
   healthy app that never learns a patch exists. The symptom reads as "the patch did
   not apply", i.e. as a Shorebird failure.
4. **`HOME` is not set on iOS.** Derive the sandbox from `Directory.systemTemp.parent`.
5. **A git worktree is not a claim.** Worktree isolation partitions BYTES; duplication
   is a collision of INTENT. Fanning out agents multiplies unclaimed intents, so the
   claim must be written *before* the fan-out, by whoever launches it.
6. **A clean cherry-pick is not a correct one.** Two individually-verified lanes
   composed into a defect neither contained, because correctness lived in the
   AGREEMENT between two call sites.
7. **`third_party/updater` is its own git checkout.** The engine repo's `git diff`
   does not see it; capturing an edit there takes a second diff, and missing it loses
   half the work while looking complete.
8. **Reasoning about a property is not verifying the signal reports it.** `0009`
   reasoned carefully about when patched Dart has run, then picked a signal that fires
   whether or not it did.
