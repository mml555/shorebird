### The dispatch table is the hard case

`dispatch_table_generator.cc:258`:

```cpp
code_ = function->CurrentCode();
entries.SetAt(selector()->offset + cid, code_);
```

Each slot is resolved from `function->CurrentCode()` at snapshot time and
called as a raw indirect branch. Nothing consults a `Function`, a `Code`
object, or a #66 dispatch cell — which is exactly the Route-B divergence
this issue names: direct → NEW while virtual → OLD.

### Candidate mechanisms — none selected

1. **Slot holds a cell-dispatching stub.** One extra indirection, paid only
   by mutable declarations' slots; the table then stays valid with no
   invalidation to get wrong.
2. **Rewrite table entries on install.** The table is a heap `uword[]` and is
   writable, but needs a serialized reverse index from declaration to every
   `(selector, cid)` slot, and one inherited `Code` appears at many cids.
3. **`CurrentCode()` itself becomes the trampoline for mutable
   declarations**, before table generation, so every snapshot-time resolver
   picks up the indirection at once.

(3) is plausible and **not approved**. The four uninventoried caches may have
different mutation semantics, and selecting a mechanism before knowing them
would be choosing on a partial inventory. Completing that inventory is the
next step.
