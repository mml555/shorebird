THE FINDING, and it is a real hole
----------------------------------
`--resolve-private-names-in-library dart:core` granted the compiled source
dart:core's PRIVATE namespace:

    a5    (flag = dart:core)              rc=0, a5.bytecode 540 bytes
    a5ctl (flag = package:p1app/...)      rc=254
          repl_dart_private.dart:5:9: Error: '_GrowableList' isn't a type.

Same body, two scopes. The only difference is which library the flag named, so
the grant came from the platform scope and from nothing else. a5ctl is the
anti-vacuity arm: without it, A5's compile could have meant `_GrowableList`
was resolvable anyway.

WHY THE CODE ALLOWED IT. `0005` guarded on `isDartLib`, which describes the
library being COMPILED, not the library the option NAMES. Its own comment
asserted the invariant -- *"Never applied to `dart:` libraries ... nothing
should be able to widen resolution into the platform this way"* -- so the
intent was documented and the enforcement was absent. A code reading agreed
with the comment; only the negative control disagreed.

WHAT IT DID **NOT** MEAN. The product was never exposed: `route_b_producer.dart`
passes `targetLibrary`, derived from the target's own identity, and a Route B
target is in an application library. The missing thing was defence in depth,
exactly where P1's objective claims a boundary.

Same probe, same fixture, same toolchain; the ONE change was the `isScheme('dart')`
refusal. RED -> GREEN on that edit is this probe's own mutation check.
