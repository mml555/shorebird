############ 2. alpha, the ordinary patch-sensitive control ############

  alpha is declared vm:never-inline and, unlike smallTarget, its computation
  does NOT appear copied into _state: _state contains smallTarget's 999/1000
  arithmetic but not alpha's string handling.

  DELIBERATELY NARROW CLAIM. _state does contain pool-indirect calls of the
  shape --patchable_static_calls emits --

    bbfb4:   ldr  x16, [x27, #0x1d28]
    bbfc0:   ldr  x0,  [x27, #0x1d30]

  -- but this excerpt does not by itself establish WHICH of them is the call to
  alpha, and an indirect call carries no symbol name to read. So alpha is
  described here as the ordinary patch-sensitive non-inlined control, evidenced
  by its BEHAVIOUR in arm 3 (OLD-a -> PATCHED-a in the same process), rather
  than as machine-proven pool indirection. The inlining claim in arm 1 does not
  depend on this: it rests on smallTarget's own computation being present in its
  callers.

############ WHAT THIS ESTABLISHES ############
  Three facts in a single run:

  1. THE REPLACEMENT REALLY ATTACHED AND IS CORRECT. The container's own
     direct invoke of the attached smallTarget returns 141 -- the value the
     banked replacement source computes. So the right bytecode was packed
     and it executes.
  2. A PATCH-SENSITIVE PATH EXISTS IN THE SAME PROCESS. alpha moved
     OLD-a -> PATCHED-a, and untargeted beta stayed OLD-b.
  3. THE INLINED COPIES STILL RUN THE OLD BODY. small=41 and callsSmall=42,
     unchanged, while the replacement that returns 141 sits attached.

  Without fact 1 the stale reading would also be consistent with the wrong
  or unchanged bytecode having been packed. It is not: the attached
  replacement demonstrably computes 141, and the ordinary source call still
  reads 41.

  So the bypass is attributable to inlining, and the argument is same-target:
  the SAME smallTarget has an attached replacement that demonstrably computes
  141 and ordinary call sites that still read 41, in one process. alpha's role
  is narrower -- it shows the release, container and apply path are working in
  that same run, so "nothing was patched at all" is excluded. No claim is made
  that alpha and smallTarget differ ONLY by inlining; they are different
  functions and the exact machine instruction reaching alpha was never
  identified.

  It fails OPEN -- APPLY ok for both targets -- which is the third such
  shape in this lane, alongside G4's two retention classes and a release
  built without --patchable_static_calls.
