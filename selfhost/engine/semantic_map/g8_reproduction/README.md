# SM1-G8 — clean reproduction, and the reporting contract (#57)

Deliberately **no `RESULT.md`**. Every number this gate reports is generated
into `evidence/` by `run_g8.sh`, and a hand-written summary beside it would be a
second copy free to drift from the first. That has happened here before: a
commit message and an issue comment carried figures from a *prior* run because
the gate had no generated report to read from. So this file explains the shape
and points at the generated artifacts; it states no measurement.

## The top-level result is not "all assertions pass"

The gate ends in the SEMANTIC-LINKER-1 four-partition shape:

    REPRODUCTION / FEASIBILITY_EVIDENCE / KNOWN_FAIL_OPEN_FINDINGS /
    PRODUCTION_PREREQUISITES

`CLEAN_REPRODUCTION` on its own is true and dangerously readable as *the
patchability model is clean*. It is not. G5 is `REDUCE_SCOPE` with zero admitted
declarations, and the fail-open mechanisms the programme depends on reproduce
here **as findings**. A reproduction can be clean precisely *because* it
faithfully reproduces refusals. The partitions keep those two facts in separate
fields so neither can be read as the other.

Generated by `lib/emit_result.py` into `evidence/g8_result.json` and rendered
into `evidence/g8_reproduction.txt`.

## Every default points at refusal

There is no path by which absent evidence yields a green field.

- `KNOWN_FAIL_OPEN_FINDINGS: ABSENT` forces `REPRODUCTION: FAIL`. A rebuild
  that stopped producing the programme's refusals would otherwise pass for the
  worst possible reason.
- A prerequisite whose binding does not resolve becomes `EVIDENCE_MISSING` and
  takes the partition to `UNDERIVABLE`. Unknown stays refusal; it is never
  converted into known-false.
- Any unreadable input is a recorded refusal rather than a traceback. A checker
  that dies on the input it is checking cannot report on it — and when it died
  mid-run it wrote no summary at all, so the arm meant to catch that input got
  no verdict.

## Prerequisite statuses are derived, not declared

Each entry in `inventory.json` under `production_prerequisites` carries a
`binding` naming real evidence — a marker in a transcript, or a path and
expectation in a JSON file — plus `implies_status`. The emitter resolves the
binding and derives the status from what the evidence implies. A `status` field
that contradicts its own binding is reported as
`STATUS_CONTRADICTS_EVIDENCE`, so **editing this inventory cannot promote a
prerequisite to `RESOLVED`**.

One binding had to be corrected during authoring: the release-mismatch
prerequisite was first bound to the bare refusal code, which also appears on a
`FAIL` line where it is the weakened-predictor control *correctly failing*. It
is now bound to the passing arm specifically.

## The reporting path has its own negatives

`lib/falsify_result.py`, report-only per the `g6c_harness` precedent. Each arm
mutates one structured input in a scratch **copy**, re-runs the emitter, and
asserts a **named partition moves to a named value** — an arm asserting only
"something failed" would pass when the wrong partition moved. Nothing under
`evidence/` is touched, so an arm cannot corrupt the bank it reports on, and no
gate is re-run.

The control is a weakened emitter that hard-codes the four happy values; it must
fail every arm. Without it the suite would prove the emitter reacts to its
input, not that it reacts correctly.

This suite immediately earned its place: it caught a real defect in the emitter,
where appending a blocker with a bare `if` in the middle of an `if/elif` chain
re-entered the chain and reset `UNDERIVABLE` back to `UNRESOLVED` — an
unresolvable binding reported as merely unresolved, on four arms.

## Why G8 is not in its own artifact inventory

The checker reads each gate's transcripts, and G8's transcript is mid-write
while the checker runs inside it, so a self-entry would digest a partial file —
the stale/absent-input class this gate exists to detect. `run_g8.sh` instead
asserts its own outputs *after* the run, which is a real check without the
circularity. `evidence/g8_result.json` is listed there for the same reason, and
its coverage comes from the reporting falsifier — stronger for a derived
artifact than a delete/corrupt pair, because it proves each partition
discriminates rather than merely that the file exists.

## Running it

    run_g8.sh <clone-src> <corpora-dir>

`<clone-src>` must be the tree that actually produced the frozen cell: it needs
both `out/host_release_arm64` and `flutter/third_party/dart` with the lineage
clone. `build_probe_corpus.sh` refuses on an unrecorded source rather than
falling back to another checkout, which is what makes a wrong argument here
visible instead of silently producing a different corpus.
