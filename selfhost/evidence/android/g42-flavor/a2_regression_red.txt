TWO THINGS THE TEST HARNESS TAUGHT, both recorded because each one silently
weakened the check:

1. patch_command_test stubs `wasParsed(any()) -> true`, so ForwardedArgs
   emitted `--dart-define-from-file=null` for every unstubbed option. That made
   the PATCH's own configuration UNFINGERPRINTABLE, and enforcement then
   correctly declined to compare -- masking the mismatch entirely. The group now
   stubs those options as not-parsed. A green run under the old stubs would have
   proved nothing.

2. Reading forwardedArgs in patch_command is a NEW argument dependency: 42
   existing tests began throwing "Null is not a subtype of bool" because
   `_flagNamed('obfuscate')` casts an unstubbed value. Fixed in the shared setUp,
   which is the honest place -- production now reads that flag.

STILL TRUE, AND WORTH KNOWING: a patch invoked with an option whose effective
define set cannot be determined (e.g. --dart-define-from-file) is NOT compared
and proceeds with a warning. That is the same rule iOS follows and is correct --
nothing can be compared -- but it means the check is skippable by that route.
