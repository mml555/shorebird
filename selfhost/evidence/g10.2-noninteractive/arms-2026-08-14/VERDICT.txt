That is precommitted outcome 11 — THE GOOD FAILURE. The guard fired, on the
release-selection prompt, by name. Mechanically it is

same harness previously exited 64 because it passed --release-version to
`release android`, which rejects that flag. So the arm asserts the log NAMES the
chooser prompt, not merely that the code is 64.

included. ci_noninteractive.sh argued the chooser "CANNOT FIRE ON ANY HOST",
because patch_command.dart reaches promptForRelease only from the

`stdin.hasTerminal && ...`. I read the same lines and predicted the same thing —
that the run would take the `else` branch and speculatively build. It did not.
The comment is corrected in place and arm 3 is now part of the harness.
