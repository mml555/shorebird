THE TRAP THIS RUN WALKED INTO, AND HOW IT WAS CAUGHT
-----------------------------------------------------------------------
`shorebird patch android` RE-RUNS `flutter build appbundle`, so after a patch
build, build/app/outputs/bundle/release/app-release.aab is the PATCH build, not
the release. I extracted an APK from it and installed that. The screen read

    CODEPATCH-V4 patch: null

which is incoherent — V4 is patch source, and no patch was applied. Looking at
the SCREEN is what caught it; every automated check up to that point was green.

Sizes confirm it after the fact:
    local post-patch aab   47,400,670 bytes
    registered release aab 47,400,740 bytes

This is the Android twin of the iOS archive trap that `launch_release_bytes.sh`
exists to prevent (`shorebird patch ios` re-archives over build/ios/archive).
**There is no Android equivalent of that guard.** The fix used here: download the
release artifact from the CONTROL PLANE and extract the APK from those bytes.
Note the download URL is SIGNED AND EXPIRES — a stale one returns 55 bytes of
{"code":"forbidden","message":"Invalid or expired URL"}, which is small enough
to be mistaken for an empty artifact rather than an auth failure.
