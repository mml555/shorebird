`Reporting failed launch` came from pid 4321 IN-PROCESS, 37 ms after `entering

Neither `shell.cc` reporter can be the source — one requires `!vm_`, the other

    onError: (Object error, StackTrace stackTrace) {
      _g15ReportLaunchFailure();
      Zone.current.handleUncaughtError(error, stackTrace);   // FORWARDS

**The white screen is a designed consequence, not a defect.** The handler forwards
the error rather than consuming it — deliberately, per its own comment, because
consuming would "suppress the app's own reporting." An uncaught root-zone error on
iOS logs and continues; `runApp()` was never reached, so no frame is ever drawn.

TWO CORRECTIONS TO THINGS CARRIED INTO THIS RUN
------------------------------------------------
1. **There is no `BOOT_FAILURE_THRESHOLD`.** It does not exist anywhere in
   `vendor/updater/library/src/`. `detect_boot_crash_on_init` calls
   `record_boot_failure` directly. **BOTH retirement paths are single-strike**, so
   "retired after one launch" does NOT identify which path fired — the log
   timestamp does. Row 2 of the precommit was written on a false premise about the
   code and is void, not failed.
2. `ReportLaunchFailure` is guarded once-per-process by a CAS on
   `launch_completed_`, shared with success — so success and failure cannot both
   report in one process.
