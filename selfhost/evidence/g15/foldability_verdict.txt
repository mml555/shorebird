==================================================

Precommitted in foldability_precommit.md before the fixture was edited. Neither

THE BEHAVIOURAL RESULT — scored first, and alone
--------------------------------------------------

    const fold   : OLD-CONST        <- foldConst(),  foldable guard
    opaque fold  : NEW-OPAQUE       <- foldOpaque(), opaque guard
    route B value: OLD-rel          <- unpatched control, unchanged
    private class: OLD-pc           <- unpatched control, unchanged

`screen_OLD-CONST_NEW-OPAQUE.png`, release 41 (`41.0.0+1`), patch 1.

Per the precommitted table, second row: **`OLD-CONST` + `NEW-OPAQUE` →
FOLDABILITY ISOLATED AS THE DISCRIMINATOR.**

Both functions are top-level, zero-argument, identically signed, called from the
same caller on adjacent lines, stored and displayed symmetrically, patched in ONE
container, and neither carries a pragma. **The only intentional difference is
whether the guard is compile-time foldable, and the behaviour split along it.**

AND `OLD-CONST` IS NOT "NEVER ATTACHED"
----------------------------------------
    sel=foldConst   rc=0 bc_post=1 uep_post_is_interpret_call=1
    sel=foldOpaque  rc=0 bc_post=1 uep_post_is_interpret_call=1
    report: targets=2, applied 2/2 targets, zero REFUSED

**The foldable target's replacement attached exactly as successfully as the
opaque one** — same return code, bytecode present, entry point moved to
`InterpretCall`. It simply never executed. That is the "attaches but the old
value executes" phenomenon, reproduced deliberately and on demand.

**That is what happened.**

THE STATIC PRE-CHECK — required, and it passed BEFORE the device run
----------------------------------------------------------------------
Recorded in `static_precheck.txt`, on release 41's shipped bytes:

    foldOpaque   0xd15b4-0xd1630  (124 bytes)   1 call site LOCATED, CONSUMED
    foldConst    0x12c7d4-0x12c7e0 (12 bytes)   0 call sites — NOT LOCATED

So `foldConst` is not merely a source-level label: **its result is statically
substituted at the caller and no call site survives in the release artifact**,
while `foldOpaque` retains a real, consumed call. The precommit required this
asymmetry be established before the device run, and it was.

THE THREE MEASUREMENTS AGREE, ACROSS THREE INDEPENDENT LAYERS
---------------------------------------------------------------
| target | STATIC (release bytes) | POOL (runtime scan) | SCREEN (behaviour) |
|---|---|---|---|
| `foldConst` | 0 surviving call sites | `ABSENT` | `OLD-CONST` |
| `foldOpaque` | 1 call site, CONSUMED | `UNIQUE` idx 6799 | `NEW-OPAQUE` |

Three layers, measured by three different instruments — a disassembly-based call
site probe, the in-engine derived pool scan, and a photograph — split the same
way on the same specimen.

**A COHERENT MECHANISM, now measured rather than argued:**

    a foldable-constant body has its RESULT substituted at every call site
      -> no call site survives to reach the Function
      -> nothing in the global object pool references it        (ABSENT)
      -> Route B attaches to the Function successfully          (rc=0)
      -> and nobody ever calls it                               (OLD on screen)

WHAT THIS MEANS FOR THE FAILING TARGET — INFERENCE, NOT VERDICT
-----------------------------------------------------------------
`killswitch_probe`'s `routeBValue() => 'OLD-kill'` is a foldable constant with no
pragma, and it measured `TPOOL_ABSENT` while rendering `OLD-kill` with a
successful attach — **the same signature this experiment produced deliberately.**

**That is a strong inference and it is NOT a verdict.** The killswitch target has
not itself been re-tested with an opaque body. `gate5_arms_precommit.md` still
requires `NEW-kill` on screen for arm A's PASS, so **arm A remains INCONCLUSIVE**
as a gate — but its phenomenon now has a measured mechanism where before it had
none.

**THE CONFIRMING RUN, and it is one line of fixture:** change `killswitch_probe`'s
`routeBValue` body to the opaque guard, keeping the target, its name, its caller
and its display unchanged, and patch it. If `NEW-kill` appears, the mechanism is
confirmed on the specimen that has failed for the entire investigation.

WHAT THIS DOES NOT CLAIM
------------------------
* NOT that arm A is explained as a gate — see above; it is INCONCLUSIVE until a

* NOT that pool presence is the mechanism rather than its consequence. ABSENT and

  cannot order them causally.
* NOT that foldability is the ONLY way to produce this phenomenon.
* NOT anything about the third corpus difference (pragma presence). Both halves
