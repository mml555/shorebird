WHERE IT STOPPED
----------------
`shorebird release ios`, ordinary user-OAuth path, exit 70:

    [HTTP] POST http://10.0.0.7:18080/token
    ShorebirdAuthException: Token refresh failed (400):
        {"code":"invalid_grant","message":"Invalid code/refresh token"}

Note what IS working: `AUTH_SERVICE_URL` sent the refresh to the SELF-HOSTED
plane, not to `auth.shorebird.dev`. That half of the earlier fix holds. The
server received the refresh and rejected the token.

AN OBSERVATION, EXPLICITLY NOT A DIAGNOSIS
-------------------------------------------
`refresh_tokens` holds **2** rows, newest `2026-08-14T23:27:36.361Z` — about one
minute before release 93 (`23:28:35Z`), i.e. minted during the gate-2 session
when refresh last succeeded. Nothing newer exists server-side.

The client is presenting a token this server does not accept. That is CONSISTENT
with a rotation whose server-side write did not persist — which would make this
the same defect as the vanished releases, showing up in the auth path. **It is
also consistent with several mundane explanations** (an ordinary rotation the
client failed to store, an expiry policy, a token superseded by the other row).
Counts and timestamps cannot separate them, and no token values were read.

Recorded as a lead with its confounds named, in the same shape the CLI
correlation is recorded — because this project has twice today promoted an
agreeable observation to a mechanism.

WHY NO RE-LOGIN WAS PERFORMED
------------------------------
1. **The stop rule.** The result does not fit a precommitted outcome, so the
   instruction is to stop, not to improvise a path to a green.
2. **The current auth state may BE the evidence.** If the rejection is caused by
   the rollback defect, re-authenticating destroys the clearest live symptom of
   it. That is the same reasoning as the precommit's rule 4 — preserve a vanish,
   do not change auth state first — applied one layer up.
3. **The credential is shared.** The other lane's user has already set the shape:
   a re-login is its own auth experiment, with exclusive ownership and before/after
   content verification, not a step inside someone else's gate.
