AND A STRUCTURAL CORRELATE THAT SURVIVES THE REFUTATION
=============================================================================

Target kind is refuted, but the trace surfaced a different split that holds:

    WORKS   RouteBThing.kindMember   TPOOL_UNIQUE   NEW-MEMBER on screen
    WORKS   kindTopLevel             TPOOL_UNIQUE   NEW-TOP    on screen
    -----------------------------------------------------------------------
    FAILS   routeBValue (killswitch) TPOOL_ABSENT   OLD-kill   on screen

**Pool presence tracks the behavior where target kind does not.** Both kinds are
UNIQUE and both work; the failing target is ABSENT and does not.

The leading candidate for WHY it is absent is the difference this precommit
already named and controlled for: **body foldability.**

    killswitch   String routeBValue() => 'OLD-kill';                  <- constant
    airgap       ... DateTime.now().millisecondsSinceEpoch >= 0 ? ...  <- opaque

A constant-returning function can have its result folded into its call sites,
leaving no pool reference to redirect — which is exactly what ABSENT reports, and
exactly what an attached-but-ineffective patch looks like.

**AND THE OBJECTION THAT KILLED THIS EXPLANATION HAS ITSELF BEEN RETRACTED.**
`gate5_armA_fold_refuted.txt` rejected the fold/inlining reading on the grounds
that release 91 worked while showing the same shape. `manual_launch_control_verdict.txt`
contradicted release 91's `NEW-kill` under its own original configuration, so that
objection no longer stands. **The fold/inlining family is revived as the leading
explanation** — not as a conclusion, and it must be MEASURED rather than argued,
since it has been wrong before.
