THE PATCH-SIDE BUG, AND ITS NEGATIVE CONTROL
--------------------------------------------
`--flavor` never arrives through the build args: `forwardedArgs` carries only
`--dart-define=` and `--enable-experiment=`, and the CLI passes flavor to
`buildIpa` as a separate parameter. So `_verifyBuildConfigAgrees` synthesised NO
FLUTTER_APP_FLAVOR for the patch while a flavored release records a real one,
and the arm it refused was the MATCHING one.

Negative control, run by reverting only `flavor: _resolvedFlavor` and re-running
the new tests — 1 passed, 3 failed, with the bug reproduced verbatim:

    FLUTTER_APP_FLAVOR: "foo" in the release, absent in this patch
    release fingerprint: f920e6ca6887128a
    patch fingerprint:   494a8de866b142b6

The one test that passes either way is "refuses an UNFLAVORED patch of a
flavored release" — it asserts behavior that was already correct, and it is kept
because it bounds the fix rather than demonstrating it. The three that flip are
the discriminating ones. The fix was restored immediately and the full suite is
green at 75/75.
