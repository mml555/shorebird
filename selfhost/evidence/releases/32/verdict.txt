WHY THIS IS A STRONGER PROOF THAN A LITERAL WOULD HAVE BEEN

  The displayed `2` is not a constant anywhere. It is the live updater's patch
  number, reached by the interpreted body traversing the app's own object graph --
  self -> widget -> runtime -> patchNumber -> toString(). So this run proves more
  than "a private getter resolved": interpreted replacement bytecode called into the
  release's live objects and formatted a runtime value.

  It also cannot be confused with either neighbouring state: the release body
  returns 'OLD-pc' and patch 1 returned 'NEW-PC', so `2` is reachable from neither.

WHAT IT CLOSES

  G3.6e was device-proven for a private FIELD read (release 31 patch 2). A field is
  named BARE in the interface and `precompiler.cc` synthesises its implicit accessors;
  a getter is a Procedure keyed `get:_name` and takes a different path to
  PruneDictionaries. That keying is listed in G3.6d's table as emitted and annotated,
  and until this run it had never executed on a device.

  patch2.capabilities.json records the grants under policy p2 with refused=0:
    _ProbeBodyState#get:_assetsPatch, _ProbeBodyState#get:_codePatch
  privateInstanceCallable=11, privateClassesConstructible=1.

  Procedure, so the same resolution and keying path is exercised, but "the same path
  is very likely" is not the same claim as a measurement.
