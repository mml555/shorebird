THE CLAIM, precommitted before the arm ran and deliberately narrow

  PARAM-ARG on the preserved release-37 binary proves that the live caller's SOLE
  POSITIONAL String argument is transferred into the interpreted replacement and is
  observable by the replacement body. A body that ignores its parameter is
  insufficient evidence.

WHAT IS NOT CLAIMED

  * ARGUMENT ORDER. There is one argument, so there is no order to get wrong.
    Multi-argument ordering needs its own two-or-more-parameter specimen and
    currently rests on the host probe's `two_params` arm (`g37_param_abi.sh`),
    which is host-only.
  * TYPE TRANSFER beyond "a usable String arrived". The body interpolates `who`
    and calls nothing on it, on purpose: calling methods on the parameter would
    drag binding and dependency reach into a gate meant to isolate the parameter
    ABI, and a failure would no longer be attributable.
  * G3.7 AS A WHOLE. Its own plan requires four shapes — `one`, `two`, `named`,
    `opt`. This fixture has one. `named`/`opt` refusal controls and `two` are NOT
    RUN, and the gate stays open.

ONE RUN DISCARDED — see DISCARDED-2026-08-13.txt

  An earlier launch produced param=PARAM-ARG from LC_UUID 2da6f295…, the archive
  `shorebird patch ios` had just rebuilt from the edited source, where paramValue
  returns PARAM-ARG natively. The mechanism played no part. It matched the arm's
  prediction exactly, which is what made it dangerous. `code_patch=none` on the same
  line was the tell.

A GAP IN THIS DIRECTORY, recorded rather than glossed

  Release 37's dSYM was NOT copied aside before the patch build, and the patch build
  overwrote the archive's dSYMs. The consumption measurement above was taken while
  the release's dSYM still existed, so it stands — but no LATER question about this
  release can be answered by symbol, because the preserved App is stripped.
  `preserve_release_evidence.sh` now copies the dSYM itself and checks its UUID
  against the App's, so this cannot recur.
