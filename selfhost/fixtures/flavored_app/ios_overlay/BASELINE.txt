#   PRODUCT_BUNDLE_IDENTIFIER   EFFECTIVE. derive_overlay.py:128 deletes the
#                               pbxproj's own setting on the Runner target's
#                               flavored configurations (one `re.sub`, count=1,

#                               Confirmed on the built artifacts: Info.plist
#                               CFBundleIdentifier is dev.selfhost.flavoredProbe
#                               .foo under build/ios/Release-Foo-iphoneos and
#                               .bar under build/ios/Release-Bar-iphoneos.
#
#   PRODUCT_NAME, DISPLAY_NAME  INERT. `PRODUCT_NAME = "$(TARGET_NAME)"` is
#                               still written in the pbxproj and a pbxproj
#                               setting beats the xcconfig that configuration
#                               includes. COUNTED 2026-08-14, because this line
#                               sits under a heading promising measurement:
#
#                                 grep -c 'PRODUCT_NAME = "$(TARGET_NAME)";' \
#                                   ios_overlay/Runner.xcodeproj/project.pbxproj
#                                 -> 18
#
#                               18 = 9 configurations x 2 NATIVE TARGETS. Every
#                               occurrence is that exact form (`grep -o
#                               'PRODUCT_NAME = .*;' | sort | uniq -c` reports a
#                               single distinct value, 18 times). The Runner and
#                               RunnerTests targets carry 9 each; the PBXProject-
#                               level configuration list carries none, which is
#                               why the count is 18 and not 27.
#
#                               CONSEQUENCE: the built bundle is Runner.app for
#                               EVERY flavor -- in the per-configuration
#                               directory (build/ios/Release-Foo-iphoneos/
#                               Runner.app) and in the final one
#                               (build/ios/iphoneos/Runner.app) alike, with
#                               CFBundleExecutable = Runner in both. There is no
#                               flavored_probe_foo.app anywhere in the build
#                               tree. Consecutive flavor builds therefore
#                               overwrite one another at ONE path: delete the
#                               build output between arms. See
#                               evidence/g42_flavored_fixture/h2_step7_supplement.txt.
#
# THE DEFINE THE SHIPPED APP RECEIVES IS THE SCHEME NAME, capitalised: `Foo`,
# not `foo`. That follows from the scheme names recorded above --
# xcode_project.dart parses the configuration, matches the scheme
# case-insensitively, and returns the scheme's own spelling. It is the single
# most consequential fact this overlay determines, and the derivation is in
# evidence/g42_flavored_fixture/h2_step7_host_arms.txt (Findings 1 and 2).
#
# A MISMATCH AT THE GATE IS "NOT APPLICABLE", NOT "UNRUN". If a Flutter bump
