## Why this is the piece it is

The host probe already answered the compiler question against a cell it staged itself; what no host run can answer is whether the **release's own AOT call site** pushes `(receiver, a, b)` such that the interpreted entry point binds them positionally. That is one measurement on one device.

It deliberately does **not** include: the fixture source change (that is `H1`); `G15`'s arming gate (no two-engine host — `PARITY.md:3124-3126`); `G4.2`/`G4.3`'s config arms (both prerequisite-blocked, `PARITY.md:2055`, `:2086`); and privacy. The host probe put its four parameter shapes on a **public** class on purpose (`probes/g37_param_abi.sh:107-109`) so a pass here can never be credited to `G3.6`. This gate keeps that separation: a public class, a public target, no `--obfuscate`, no `--flavor`, no `--dart-define`.

## Open questions

1. **Who cuts the release — `H1` or this order.** This order takes it, so `R6`'s version counter and `R8` stay with the holder of `R1` and the release's reachability baseline is measured by the person who will read it. The alternative is `H1` cutting release 37 itself and handing over a preserved specimen; that shortens this order but splits `R6` across two claims and lets a fixture change land without anyone having watched it reach the phone. Decide before either starts, and record it in the claims table.
2. **One release or two for the four arms.** All four shapes on one release makes the refusals same-release controls, mirroring `g37_param_abi.sh:44-46` and the reasoning that made release 23's different-release control worthless (`PARITY.md:3239`). Cost: two extra methods that exist only to be refused. A second release for the refusals is strictly weaker; take it only if adding them perturbs the live rows.
3. **Whether to add a third live arm with a non-`String` return.** The host probe varies parameter types but always returns `String` because a widget row displays it. A returned `int` would test the return path too; it needs a formatting step that could itself fold. Cheap to add, easy to make meaningless.
4. **Whether reachability deserves a probe.** Today it is two human observations (step 8). A gate that read the release's `.dill` or its disassembly and reported "this site is on a path from `main`" would close the class `c0619d13` opened, the way `assert_result_consumed.sh` closed the fold class after six wasted device runs. Cost: it is a real static-reachability analysis over AOT output, and a wrong one would be worse than none — it would launder an assumption into a gate.
