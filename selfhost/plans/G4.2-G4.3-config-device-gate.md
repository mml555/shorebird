## Open questions

* **Should arm 2 ever become reachable?** Making the fingerprint able to see a plain patch of an obfuscated release means *not* auto-injecting `--obfuscate`, which breaks upstream's ergonomics — `patch_command.dart:636-641` explicitly tells users the flag is unnecessary. And `H4` makes it moot for now: without `--load-obfuscation-map` the patch build cannot complete either way. Tradeoff: an unreachable refusal path that unit tests cover, versus a behaviour change to a shared upstream code path with its own acceptance. Recommended: leave the auto-injection, keep arm 2 a KNOWN GAP with the citation, and revisit only if `H4` lands.
* **Where does the Android configuration check belong?** Android has no `RouteBBuildConfig` anywhere (measured: 0 hits in both `android_patcher.dart` and `android_releaser.dart`). Either the fingerprint generalises to the diff path — real work, real value, since `--dart-define` mismatches are as silent there — or the Android rows stay INHERITED with the gap named. Deciding this changes B5's meaning from "what refuses today" to "what should refuse".
* **Evidence numbering for a second fixture.** `airgap_app` is at `36.0.0+1` and `selfhost/evidence/releases/` holds 24-32, 34, 35, 36. The draft's proposed `40.0.0+1` for a flavored fixture now leaves a 3-release margin, not 7. Either give the second fixture a distinct band (`200.x`) or add a fixture field to the flat `releases/<n>/` namespace — cheap now, annoying later. `H2` will have to settle it.
* **Should a flavored fixture's platform trees be tracked?** `.gitignore:36-40` excludes `airgap_app/{ios,android,.dart_tool,build}` as "generated, reproducible from the committed sources by `prepare_airgap_fixture.sh`", and `:44` excludes its `shorebird.yaml`; `prepare_airgap_fixture.sh:32` hard-wires `FIXTURE` to `airgap_app`. * **Does `G4.3` keep its §16 rule 1 claim on `R1`?** As written (PARITY.md:2742-2743) it does, and as measured it holds nothing runnable on the phone. Leaving the row is honest about intent and dishonest about contention; editing it needs the correction rule's evidence, which this order supplies.
